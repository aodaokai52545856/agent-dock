# 系统 Claude 身份与 usage 不一致

以下账号标识已匿名化。

2026-10-24，用户反馈账号 A 在网页显示已用 71%，但 Claude Code 的 `/usage` 显示为空。

只读核验发现系统目录存在明确的身份错配：`.claude.json.oauthAccount` 显示账号 A，但当前凭证向 Anthropic 官方 profile 接口查询时，返回账号 B。官方 usage 接口正常返回 HTTP 200，5 小时使用率为 2%、每周为 0%；这些值属于账号 B，不能拿来与用户所述账号 A 的 71% 比较。

缓存的 `cachedUsageUtilization.accountUuid` 也记录了账号 A 的 UUID，说明仅检查缓存中两个 UUID 是否相等，不能证明额度属于当前显示的账号。独立目录中的另一个已迁移账号经官方接口核验，身份与凭证一致。

本次没有复现用户所见的 `/usage` 空白渲染，因此不能断言空白完全由这处错配造成。已证实的是系统登录标签错误，且系统凭证返回了另一个账号的额度。

修复覆盖系统入口的缺口：

- 系统登录需要实际身份核验，不能只凭本机缓存显示已登录并允许切换。
- 核验结果绑定访问令牌指纹；令牌变化后重新核验，错误归属不会被旧检查结果掩盖。
- 正常启动系统订阅会话时自动检查尚未核验的凭证；核验失败或错配时停止启动。
- 错配结果在重启后仍可显示，界面给出实际邮箱的脱敏提示。
- 身份检查失败后刷新列表，及时显示冲突；新增“检查登录”入口。
- 系统入口不会被固定到以前保存的账号 UUID，后续外部正常更换账号仍可重新核验。

恢复账号 A 的正确使用方式是在其「待迁移」条目中完成独立登录，再设为默认并新建会话。原有系统登录和旧快照保留。诊断及自动校验不刷新、不复制、不改写真实凭证，不执行退出或重新登录。
