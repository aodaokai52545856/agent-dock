# Claude 账号切换故障调查

调查日期：2026-10-22，America/Los_Angeles。Claude Code 本机版本：2.1.309。

## 结论

本机账号快照已经出现两类实际损坏：一个快照的访问令牌、刷新令牌均为空；另一个快照的账号元数据与令牌实际所属账号不一致。项目仍会接受这些快照、显示已登录并返回切换成功。空快照会直接使 Claude Code 要求重新登录；错配说明当前快照保存方式不能保证切换到用户选中的身份。

此外，两个旧快照的访问令牌已经过期，但其刷新令牌记录的到期时间尚未到达。**仅凭访问令牌过期，不能认定这两个账号必须重新登录。** 本次没有执行令牌刷新，因此没有核实它们是否仍可续期。

## 项目代码中的问题

1. **用身份缓存代替登录状态。** `src-tauri/src/claude_accounts.rs:370` 的 `read_live_identity` 从 `.claude.json.oauthAccount` 读取身份；`:392` 的 `identity_from_account` 只要求邮箱或账号 UUID 存在，既不要求有效令牌，也不校验令牌对应身份。`:125` 据此设置 `logged_in`。

2. **读取列表会把坏凭据保存回快照。** `src-tauri/src/claude_accounts.rs:104` 的 `list_accounts_in` 首先执行 `persist_live`。`:204` 的保存逻辑依据缓存身份选择快照，随后直接保存当前 OAuth 对象，未拒绝空令牌，也未核验归属。它既能用空令牌覆盖已有快照，也能把 A 的令牌保存进 B 的快照。`:132` 的手动保存也存在相同的身份校验缺口。

3. **切换只检查对象结构，不检查是否能登录。** `src-tauri/src/claude_accounts.rs:162` 的 `switch_account_in` 只要求 `claudeAiOauth` 和账号缓存是 JSON 对象，随后直接写入实时配置。空字符串令牌同样可以通过；没有刷新、实际身份核验或失败回滚。

4. **停止旧终端的顺序存在并发风险。** `src/components/ClaudeAccountDialog.vue:82` 先等待后端完成写入，再发出 `switched`；`src/App.vue:602` 收到事件才关闭旧 Claude 终端。切换期间旧进程仍可能刷新、清空或写回全局凭据，而切换逻辑没有与它协调的锁。这是代码中存在的风险，尚无日志证明它就是本机这次错配的最初触发点。

## 为什么之前能用，现在反复要求登录

保存时间较近、凭据完整且身份匹配时，上述实现能够完成文件切换。令牌后来被刷新、清空或与身份缓存不同步后，程序仍按原来的逻辑判定成功，导致界面状态与 Claude Code 的真实认证状态分离。这与本机已经观察到的空快照、身份错配相符。

账号模块自引入后没有后续代码变更。本机 CLI 最近更新到 2.1.309，但现有证据不足以认定此次更新是根因。也没有足够的历史认证日志还原最初哪次操作清空了令牌、哪次写入制造了错配。

## 修复建议

优先修复代码，再修复已损坏快照：

1. 将缓存身份和可用认证状态分开；拒绝把两个令牌均为空的状态保存回账号快照，读取列表不应盲目覆盖已有凭据。
2. 保存、登录完成和切换成功时核验实际账号归属；发现快照身份错配时明确报错，避免继续传播。
3. 串行执行切换，先停止并等待旧 Claude 进程退出，再保存一致的当前状态、恢复目标凭据；失败时恢复原状态。
4. 对访问令牌过期且刷新令牌存在的账号，通过 Claude Code 的认证流程尝试续期；只有无法续期时才要求重新登录。不要把访问令牌到期直接等同于账号失效。
5. 当前 GMX 实时登录有效，可在校验归属后重新保存；Gmail 标签现有快照不能证明拥有 Gmail 登录，需要重新取得该账号的正确凭据。Apple、Hotmail 应先核验续期能力。

长期可以评估官方建议的每账号独立 `CLAUDE_CONFIG_DIR`，减少共享全局凭据的竞争；项目现有的会话历史共用需求需要同时处理。

## 后续：第一版修复

用户随后授权修改，第一版已完成以下实现：

- 账号列表改为只读；空令牌不再被当作已登录，也不会自动覆盖已有快照。
- 保存、切换前调用官方 profile 接口核验账号 UUID，拒绝把另一个账号的令牌当作目标账号使用。
- 对过期访问令牌或提前收到的 401 尝试续期；新令牌先落盘，后续核验遇到网络错误时可从新令牌继续重试。若服务端未返回新刷新令牌，保留原值。
