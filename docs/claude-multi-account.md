# Claude 多账号管理

从系统菜单打开「Claude 账号」。左侧选择账号，右侧管理登录、默认账号和代理。

1. 点击「添加账号」，输入名称，可选直连或该账号独立的 HTTP(S) 代理。
2. 点击「登录账号」，在 Claude 打开的浏览器中授权。可取消等待，账号目录会保留。
3. 登录通过身份检查后点击「设为默认账号」。之后新建的 Claude 会话使用此账号。
4. 需要同时使用另一个账号时，将另一个账号设为默认再新建会话；已有终端继续使用原账号。

「系统 Claude」直接使用启动 Dock 时的原有 Claude 配置目录与登录。应用不会把新账号写入系统目录，也不修改 shell 启动脚本。此入口可改名和设置代理；系统账号需要重新登录时，在系统终端运行 `claude auth login`。

## 原理与路径

参考 [multi-claude](https://github.com/jakoes-wu/multi-claude) 的 `env.py`、`launcher.py`、`identity.py`，将核心机制适配到 Rust 与 Tauri，而不是调用 Python CLI：

- 账号索引：应用数据目录下 `claude-accounts/profiles.json`，不包含令牌。
- 新账号目录：`claude-accounts/profiles/<uuid>/`。启动时仅为子进程设置 `CLAUDE_CONFIG_DIR`，不修改 Dock 自身或系统的环境变量。
- 凭证、`.claude.json`、设置、会话历史各自独立；令牌登录和续期交给 Claude Code。
- macOS 钥匙串服务名使用配置目录（NFC）的 SHA-256 前 8 位后缀；系统默认身份使用原服务名。
- 启动器清除继承的 API key、OAuth token、自定义认证地址和安全存储目录；在 shell 启动文件执行后再次应用账号环境，避免重新引入全局凭证。
- 原账号设置与项目设置中的认证覆盖项会提示冲突。仅报告键名，不显示密钥内容。项目中的 API 配置需要按实际用途调整后再使用独立订阅账号。
- 代理优先级：账号指定代理/直连 > 项目代理；登录时的「跟随」使用应用默认代理及进程环境。自定义代理清除继承的 `ALL_PROXY` 并保留本地 OAuth 回调地址的直连。

列表只读本机状态，不联网、不刷新或保存凭证。「本地已登录」表示检测到非空凭证；「待续期」由 Claude 下次启动时尝试续期，并不保证服务端仍允许续期。登录结束通过只读 profile 请求核验身份，网络失败显示「待核验」，可点击「检查登录」重试。

系统入口需要额外核验：首次显示「待核验」，点击「检查登录」或启动系统账号会话时，通过官方 profile 接口确认当前凭证与本机身份缓存一致。检查结果按访问令牌的 SHA-256 指纹保存在应用索引，令牌变化后失效。发现错配会显示实际凭证所属邮箱（脱敏）并阻止继续按错误身份启动；不修改系统凭证或身份缓存，不执行令牌刷新。外部终端更换系统账号后需重新核验。

## 旧快照与历史

旧版 `index.json` 中的账号显示为「待迁移」。点击「迁移并登录」，使用原邮箱重新授权，建立新的独立身份。**不复制旧快照令牌**，以免旧全局进程和新账号同时续期同一份刷新令牌。原快照与诊断/恢复文件保留。

会话列表汇集原系统目录及各独立账号目录。新建会话使用默认账号；恢复历史会话按文件所属目录选择账号。若同一会话 ID 存在于多个目录，拒绝自动恢复/改名/删除，避免操作错误账号。

「移出账号列表」只取消注册，保留目录、凭证和历史；已有会话继续运行，历史会话仍可恢复。移除默认账号后新会话回到系统 Claude。重新登录某个账号前需要关闭该账号的终端，其他账号继续运行。

## 验证

`npm run test:claude`、`npm run build`；Rust 使用 `cargo test claude`、`cargo test pty`。测试凭证为虚构值，存于临时目录；不对真实账号执行登录、切换或刷新。
